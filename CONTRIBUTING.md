# Contributing to mipland

Thanks for contributing. This repo is part of the Monad Open Source Track
(MOST), so it holds a consistent bar for how work lands here.

## How work lands

All changes go through a pull request. Direct pushes to `master` are
turned off, and every pull request needs an approving review from @portdeveloper
before it can merge. That review is the bar: a merge means the work was read and
accepted, not just that it was opened.

## Before you open a pull request

- Search existing issues and pull requests so you are not duplicating work.
- Open or pick up an issue that describes what you are doing.
- Keep each pull request to one thing. Do not mix a feature with unrelated
  style or refactor changes.
- Write your own original code. If you build on a fork or a template, the value
  you add on top is what counts.
- Run the project locally and confirm your change works before you push.

## What makes a good contribution

- A commit that moves the project forward: a feature, a fix, a test, or docs.
- A clear description of what changed and why, linked to an issue where you can.
- Changes small enough to review in one sitting.

Work that only pads the history (whitespace, reformatting, generated files, or
commits with no real change) does not count and will be asked to be revised.

## Getting started

Clone the repo, install dependencies, and run it locally. See the README for the
project-specific commands. If a step is unclear, open an issue and we will fix
the docs.
